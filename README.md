# Алиса + Gemini + Serper

Шаблон личного голосового помощника для Яндекс Станции. Gemini отвечает на вопросы, Serper ищет актуальные сведения, Upstash Redis хранит контекст, а Vercel принимает запросы Алисы. После размещения домашний компьютер можно выключить.

Каждый пользователь создаёт **свои** аккаунты, API-ключи, базу данных и навык. В репозитории нет общего сервера или чужих ключей. Название навыка вы выбираете сами.

## Что умеет

- Обычный диалог и уточнения с учётом последних реплик.
- Поиск для новостей, погоды и других изменяемых фактов.
- Короткие ответы без автоматического перечисления источников.
- Источники последнего ответа доступны отдельной командой; ссылки появляются на устройствах с экраном.
- История до 12 сообщений с ограниченным сроком хранения, сброс истории и дневной лимит вопросов.

Приветствие: «Привет! Задай вопрос. Команды — “справка”».

| Команда | Действие |
|---|---|
| Справка | Перечислить команды; также работают «помощь», «что ты умеешь» |
| Чек | Получить результат после «Готовлю ответ»; если не готов, повторить через несколько секунд |
| Повтори | Повторить последний результат без новой генерации |
| Источники | Озвучить источники последнего результата и показать ссылки; также «откуда информация», «откуда ты это знаешь» |
| Забудь разговор | Очистить историю, источники и отменить незавершённый ответ |
| Выход | Завершить сессию навыка |

«Чек» — отдельная реплика. Слово «продолжай» больше не служебная команда: оно передаётся модели как обычное продолжение разговора.

## Как устроено

```text
Яндекс Станция → Яндекс Диалоги → Vercel /api
                                  ├─ Gemini: планирование и ответ
                                  ├─ Serper: поиск
                                  └─ Upstash Redis: история и готовый результат
```

Сервер старается ответить за 2,6 секунды. Если генерация дольше, возвращает «Готовлю ответ… скажи “чек”» и продолжает через `waitUntil`. Команда «Чек» забирает результат из Redis. Колонка не начинает говорить сама после завершения работы. Это ограниченная фоновая обработка, а не гарантированная очередь заданий.

## Что понадобится

- Аккаунт Яндекса и колонка на том же аккаунте.
- GitHub и Vercel для кода и размещения.
- Доступ к Gemini API и модель с поддержкой `responseJsonSchema` (structured outputs).
- Serper API key и Upstash Redis с REST-доступом на чтение и запись.
- Node.js 22 для локальной разработки (для загрузки через сайт GitHub установка Node не нужна).

ChatGPT Plus не требуется. Бесплатные квоты сервисов могут подойти для небольшого личного использования, но их доступность, лимиты и региональные условия нужно проверить в своих кабинетах. Шаблон не включает платный биллинг и не обещает бессрочную бесплатность.

## Установка с нуля

### 1. Создайте собственную копию репозитория

Используйте **Use this template**, если владелец включил Template repository в GitHub Settings, либо создайте новый репозиторий и загрузите содержимое этой папки.

Если загружаете через сайт GitHub, перетащите **папки целиком**, сохранив структуру:

```text
api/index.js
lib/app.js
lib/common.js
lib/providers.js
lib/store.js
scripts/
tests/
.env.example
.gitignore
package.json
pnpm-lock.yaml
vercel.json
LICENSE
NOTICE.md
```

Не загружайте ZIP вместо исходников, `node_modules`, настоящую `.env`, снимки кабинетов и логи с секретами. Исходники можно распространять публично; рабочую копию со своими дополнительными файлами удобнее держать приватной.

### 2. Подготовьте сервисы

1. В [Google AI Studio](https://aistudio.google.com/) создайте ключ. Выберите доступную текстовую модель с structured outputs и запишите её точный ID. Модель намеренно не зафиксирована в примере: доступность меняется. [Документация ключей](https://ai.google.dev/gemini-api/docs/api-key), [structured outputs](https://ai.google.dev/gemini-api/docs/structured-output), [регионы](https://ai.google.dev/gemini-api/docs/available-regions).
2. В [Serper](https://serper.dev/) получите ключ и проверьте остаток запросов.
3. В [Upstash](https://console.upstash.com/) создайте Redis, желательно близко к региону Vercel. Скопируйте REST URL и обычный read-write REST token, а не read-only token. Обычный `REDIS_URL` не заменяет REST URL. [Документация REST](https://upstash.com/docs/redis/features/restapi).

### 3. Создайте навык Алисы

В [Яндекс Диалогах](https://dialogs.yandex.ru/developer/) создайте навык. Выберите приватный доступ, уникальное имя минимум из двух слов, описание, примеры активации, категорию и свою иконку. Не включайте «Нужно устройство с экраном» для обычной колонки. Скопируйте ID именно этого навыка из адреса страницы. Webhook добавляется после размещения.

После удаления и повторного создания навыка ID меняется: обновите его и на сервере. [Настройки публикации Яндекса](https://yandex.ru/dev/dialogs/alice/doc/ru/publish-settings).

### 4. Разместите на Vercel

Импортируйте репозиторий: **Add New → Project**. Framework Preset — **Other**, Root Directory — папка с `package.json` и `api/`. Пользовательские Build Command и Output Directory не нужны. Runtime — Node.js 22.x; в `vercel.json` задано 60 секунд на функцию. [Node.js Functions](https://vercel.com/docs/functions/runtimes/node-js).

В Environment Variables заполните значения для **Production**:

| Переменная | Значение |
|---|---|
| GEMINI_API_KEY | Собственный ключ Gemini |
| GEMINI_MODEL | Точный ID доступной модели |
| SERPER_API_KEY | Собственный ключ Serper |
| UPSTASH_REDIS_REST_URL | HTTPS REST URL вашей базы |
| UPSTASH_REDIS_REST_TOKEN | Read-write REST token |
| ALICE_SKILL_ID | ID вашего навыка Яндекса |
| WEBHOOK_SECRET | Собственный случайный секрет минимум 32 символа |
| ALLOWED_USER_IDS | Сначала пусто, после проверки — разрешённые user_id или application_id через запятую |
| TIMEZONE | Ваш часовой пояс IANA; по умолчанию UTC |
| HISTORY_TTL_SECONDS | 86400 — сутки; допустимо 300–604800 |
| DAILY_QUESTION_LIMIT | 50; допустимо 1–1000 |

Создать секрет локально:

```sh
node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"
```

Нажмите Deploy. После изменения переменных нужен **Redeploy**. При подключении preview-развёртываний используйте для них отдельные тестовые ключи и базу.

### 5. Подключите обработчик и проверьте

Откройте `https://YOUR-PROJECT.vercel.app/api`: ожидается `{"ok":true,"service":"alice-gemini-search"}`. Это проверка доступности обработчика, а не всех API. Ошибка 404 на `/` нормальна: главной страницы нет.

В Backend навыка укажите:

```text
https://YOUR-PROJECT.vercel.app/api?token=YOUR_WEBHOOK_SECRET
```

Подставьте свой домен и секрет. Используйте production-домен, доступный Яндексу без входа в Vercel. Полный URL — секрет, не публикуйте его.

Сохраните навык, откройте **Тестирование** и проверьте:

1. Запуск — короткое приветствие; «Справка» — список команд.
2. «Почему небо голубое?» — обычный ответ.
3. «Найди новости моего города за сегодня» — уточнение города, если его ещё нет в контексте.
4. После ожидания — «Чек»; ответ не должен перечислять источники автоматически.
5. «Источники» — источники и ссылки; самостоятельно проверьте факты и даты.
6. «Повтори», затем «Забудь разговор», затем «Источники» — сохранённые источники должны исчезнуть.

В JSON запроса тестера найдите `session.user.user_id` (либо `session.application.application_id`). Внесите его в `ALLOWED_USER_IDS` и выполните Redeploy. Проверьте отдельно колонку: если используется другой разрешённый ID, добавьте его. Не копируйте ID другого владельца шаблона.

### 6. Запустите на колонке

Заполните обязательные поля, сохраните, отправьте приватный навык на автомодерацию и нажмите «Опубликовать», когда кнопка станет доступна. Дождитесь завершения публикации. Колонка должна быть на аккаунте владельца навыка. Скажите: «Алиса, запусти навык [ваше название]». [Тестирование Яндекса](https://yandex.ru/dev/dialogs/alice/doc/ru/test).

## Обновление установленной копии

Замените код в своём репозитории, сохранив переменные Vercel. Проверьте успешный новый production deployment. Изменения только обработчика не требуют пересоздания навыка. Если меняете настройки карточки в Яндексе, опубликуйте новую версию по правилам консоли.

При переходе с версии с «Продолжай» скажите «Забудь разговор»: старый готовый ответ в Redis может содержать старое перечисление источников. Приветствие и «Справка» помогут проверить, что обновлён именно production-сервер.

## Локальная разработка

```sh
npm install
npm test
npm run smoke
node scripts/dev.js --demo
```

Тесты и демо не используют реальные ключи. Для реального запуска скопируйте `.env.example` в `.env`, заполните значения, затем выполните `npm run check` и `npm run dev`. Сервер слушает только localhost. В репозитории есть pnpm lockfile; для воспроизводимой установки используйте `pnpm install --frozen-lockfile`.

## Ограничения и данные

Поиск использует фрагменты выдачи, а не полные статьи. Модель может ошибаться в выборе поиска, дат и источников. Инструкция модели запрещает перечисление источников в обычном ответе, но вероятностная генерация не даёт абсолютной гарантии; приложение само никогда не дописывает атрибуцию. Издания озвучиваются по полю publisher, при его отсутствии — по домену. Ссылки иногда ведут через Google; приложение их не разворачивает автоматически.

Команда «Источники» относится к последнему результату: после нового вопроса прежний список заменяется. При ошибке или отсутствии поиска список может быть пустым. Справка и чтение результата не расходуют новые вызовы модели. Обычный вопрос обычно требует двух вызовов Gemini и, при поиске, одного Serper.

Текст вопросов и история передаются Google, поисковые запросы — Serper, история и результаты хранятся в Upstash, обработка выполняется на Vercel. ID в ключах Redis хешируются; сами сообщения не шифруются приложением. На общей колонке контекст может быть общим. Сброс разговора не очищает технические логи провайдеров и дневной счётчик.

`waitUntil` ограничен временем функции. Сбой/холодный старт может привести к потере работы или превышению таймаута Алисы; после 65 секунд задание считается просроченным. При сбое поиска ответ по памяти не подменяет свежие сведения. Дневной лимит не заменяет ограничения расходов в кабинетах.

## Если не работает

| Симптом | Что проверить |
|---|---|
| `unused_function api/index.js` | Папка `api` загружена целиком; Root Directory содержит её и package.json |
| `Skill not found` в консоли | Навык существует на текущем аккаунте; не открыта вкладка удалённого навыка |
| 403 | WEBHOOK_SECRET и ALLOWED_USER_IDS |
| 400 Invalid Alice request | ID навыка и формат запроса |
| «Навык пока не настроен» | Обязательные env, окружение Production, новый Redeploy |
| Ошибка нейросети | Модель, ключ, квота и региональные ограничения Google |
| Не проверены свежие сведения | Serper, квота и наличие результатов |
| Медленно отвечает хранилище | REST URL/token Upstash, регион, доступность |
| «Чек» не работает | Обновился ли production deployment; не старый ли код |
