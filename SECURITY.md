# Безопасность и границы применения

Шаблон предназначен для личного навыка. Он не является аттестованной системой защиты информации и не гарантирует соответствие требованиям вашей организации или законодательства для конкретного вида данных.

## Что не публиковать

- `.env`, ключи Gemini и Serper, токен Upstash, WEBHOOK_SECRET и полный URL вебхука.
- Собственные ID пользователей и навыка, выгрузки Redis, журналы запросов и снимки кабинетов.
- Git-историю рабочего приватного проекта: новый шаблон следует создавать отдельно из проверенных файлов.

`.gitignore` предотвращает случайное добавление новых файлов, но не удаляет уже закоммиченные секреты. Если секрет попал в историю или открытый журнал, отзовите/замените его у провайдера; простого удаления файла недостаточно.

## Модель доступа

Webhook проверяет случайный секрет длиной от 32 символов, ID навыка и при настройке ALLOWED_USER_IDS список разрешённых пользователей. ID навыка сам по себе не удостоверяет отправителя. При утечке секрета поля запроса можно подделать, поэтому allowlist не заменяет защиту секрета.

Секрет находится в query string: полный URL может попасть в журналы хостинга, историю браузера и снимки экрана. Не открывайте полный webhook как обычную ссылку и не публикуйте необработанные логи. Для проверки доступности используйте GET /api без токена.

Пустой ALLOWED_USER_IDS допускается для первоначальной настройки. После проверки укажите собственные ID. Развёртывание отдельное для каждого владельца; не используйте шаблон как публичный общий сервис без дополнительной защиты от злоупотреблений и общего лимита расходов. Текущий дневной лимит действует на пользователя, а не на весь сервер.

## Обработка данных

Вопросы и короткая история поступают Google, поисковая фраза — Serper, история и источники — Upstash; сервер работает на Vercel. HTTPS защищает передачу, но в приложении нет сквозного шифрования содержимого Redis. Хеширование ID не обезличивает текст сообщений. Сервисные логи и политики хранения каждого провайдера независимы от команды сброса истории.

Не передавайте через навык пароли, платёжные данные, коммерческие секреты и сведения, для которых эти внешние сервисы не одобрены. Проверьте условия обработки данных и настройки тарифа каждого провайдера.

Поисковые фрагменты считаются недоверенными. Инструкции модели ограничивают их использование, однако не исключают prompt injection и фактические ошибки. Модель не имеет инструментов выполнения команд на сервере и не получает значения API-ключей в промпте.

## Проверка перед публикацией своей копии

Просмотрите весь список файлов и git diff, проверьте историю и секреты, используйте GitHub secret scanning, если доступен. Сохраняйте токены только в переменных хостинга, используйте отдельные тестовые и рабочие аккаунты/базы при необходимости. Ограничьте доступ к Vercel и Upstash, настройте лимиты у провайдеров, обновляйте зависимости и проверяйте advisories.

В публичном GitHub видны владелец репозитория и метаданные коммитов. Используйте GitHub noreply email, если не хотите раскрывать личную почту. Публичный репозиторий не означает анонимность автора.

## Сообщения об уязвимостях

Не размещайте секреты или данные реальных пользователей в публичных issues. Используйте приватный канал владельца либо GitHub Private vulnerability reporting, если он включён. К сообщению приложите минимальный пример с вымышленными значениями.
